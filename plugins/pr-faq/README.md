# pr-faq

`/pr-faq [idea]` — draft Amazon's Working Backwards artifact (a future press
release plus FAQ) before any code gets written, and apply its actual kill
criterion at the end.

```
/pr-faq                                   # ask what we're building
/pr-faq a dashboard that shows churn risk # seed the elicitation
```

## What it changes

Most "write me a press release for my idea" prompts produce enthusiastic
copy. This skill exists because that's not the point of a PR/FAQ — the point
is that the customer benefit has to survive being stated plainly, and if it
doesn't, the idea is supposed to die there, before anyone builds anything.

Five steps: elicit the customer and the pain point directly (not multiple
choice — these are open questions), draft the one-page press release in
Amazon's fixed shape, draft a genuinely separate External/Internal FAQ, then
a mandatory kill test that has to render one of three real verdicts —
**survives**, **survives with a named gap**, or **killed** — not just a pass
by default. The verdict gets written into the saved doc, not spoken and
dropped.

## The honest limitation

This produces a single self-graded draft. One author, one pass, no
independent reader who didn't write it — Amazon's actual process runs a
PR/FAQ through several rounds of real stakeholders. Treat a "survives"
verdict from this skill as provisional. If the stakes are high, hand the
sub-heading and the Internal FAQ to someone who didn't write them and see if
it survives contact with a reader who isn't anchored on their own draft.

## Not IDEO's instrument

This vault's own research ([[backwards-design-narrative-vs-prototype-instrument]])
found the two reverse-from-an-imagined-end-state instruments this genre
gets compared are structurally different: Amazon's is a critiqued
*narrative* (this skill); IDEO's ("Future Headlines," Method Cards, since
2003) is an enacted *prototype/exercise*, tested live with people, not
written and graded on a page. This skill covers the narrative half only —
deliberately, since a document is something a skill can actually gate on,
where a live exercise mostly isn't.
