# drunk

`/drunk <subject>` — explain something to a reader who **knows the domain**,
possibly wrote the thing, but has no working memory, no patience, and no
error-checking left.

```
/drunk                    # the last substantive technical thing
/drunk --last             # same
/drunk task #73           # a specific subject
```

## What it changes

The one rule: **the answer goes in the first sentence.** Not the context, not
the caveat, not what was checked. Then every constraint that follows exists to
protect that: do the arithmetic rather than putting two numbers on the page,
flatten conditionals to the branch the reader is actually in, restate referents
because they don't remember the last message, no lists longer than three.

## Not `/elii`

They sound alike and mean opposite things.

|  | lacks | you supply |
|---|---|---|
| `/elii` | background | **more** context |
| `/drunk` | bandwidth | **less**, in a better order |

Confusing them produces a condescending answer to a competent person. That is
the cardinal failure this skill names, because the register sounds like ELI5 and
ELI5 assumes ignorance.

## The reason it isn't only an accessibility skill

An impaired reader fails in exactly the ways a degraded agent fails — skipping
arithmetic, acting on a partial read, taking the first plausible answer. So
anything written to survive them is also a probe of the prose itself.

Read your own output as this reader and ask what they would *do*. If the answer
is "the wrong thing, confidently," the writing is broken even when every fact in
it is correct — a failure invisible to tests, which is why it needs a human.

## Provenance

Written 2026-08-13 during a deliberate drunk-usability test, in which the
operator drank and then worked their own task list to find where the harness
assumed a clear head. The skill's named "comfort trap" failure mode — telling an
impaired reader to go to bed instead of answering — is recorded because it
happened during that test, an hour before the skill existed.
